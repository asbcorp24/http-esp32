# http-esp32

Прошивка для `ESP32` на `PlatformIO/Arduino`, которая:

- измеряет температуру и ток по 3 фазам;
- рассчитывает мощность и контролирует перекос фаз;
- управляет реле насоса;
- включает обогрев платы по температуре;
- сохраняет измерения в локальную очередь `LittleFS`;
- отправляет данные на сервер через `GSM/GPRS`;
- позволяет настраивать параметры через Wi-Fi AP режим.

## Что реализовано

- Wi-Fi режим настройки по кнопке на `GPIO4`
- Web UI для изменения:
  - `serverHost`
  - `serverPort`
  - `cryptoPass`
  - `location`
  - `voltage`
  - интервала опроса/отправки `15-60` сек
  - допустимого перекоса фаз `0-20%`
  - логина и пароля админа
- 3 датчика тока
- 2 датчика температуры `DS18B20` на одной шине
- защита насоса по перекосу фаз с защелкой аварии
- удаленное управление реле насоса с хоста
- буферизация телеметрии в кольцевом файле
- AES/HMAC защита полезной нагрузки

## Актуальная распиновка

- `GPIO4` - кнопка входа в Wi-Fi config mode
- `GPIO2` - светодиод индикации Wi-Fi режима
- `GPIO34` - датчик тока 1
- `GPIO32` - датчик тока 2
- `GPIO33` - датчик тока 3
- `GPIO26` - реле насоса
- `GPIO12` - реле обогрева платы
- `GPIO18` - шина `DS18B20` для 2 датчиков температуры
- `GPIO16` - `GSM RX`
- `GPIO17` - `GSM TX`
- `I2C` - `RTC DS3231`

## Режимы работы

### 1. Wi-Fi config mode

Устройство входит в режим настройки, если при старте `GPIO4` замкнут на `GND`.

В этом режиме:

- поднимается точка доступа `ESP32-CONFIG`
- пароль: `12345678`
- адрес панели: `http://192.168.4.1/`
- доступ к панели защищен логином и паролем из `Preferences`

### 2. Normal mode

В обычном режиме прошивка:

- читает 3 канала тока;
- читает до 2 датчиков температуры;
- управляет обогревом платы;
- анализирует перекос фаз;
- отключает насос при аварии по перекосу;
- складывает измерения в локальную очередь;
- периодически получает команду реле с хоста;
- отправляет накопленные записи через GSM.

## Логика перекоса фаз

Перекос фаз считается по отклонению токов `I1/I2/I3` от среднего значения.

Поведение:

- если средний ток слишком маленький, перекос не анализируется;
- если перекос больше настроенного порога, реле насоса отключается;
- состояние аварии защелкивается;
- повторный запуск возможен только после новой удаленной команды на включение реле.

## Формат телеметрии

Каждая запись содержит:

- `ts`
- `current1_mA`
- `current2_mA`
- `current3_mA`
- `power_dW`
- `temp1_cC`
- `temp2_cC`
- `phase_imbalance_dPct`
- `relay_on`
- `heater_on`
- `phase_trip`
- `relay_cmd_on`

## Серверные маршруты

Пример серверной части лежит в файле [index (2).php](/E:/dev/http-esp32/index%20(2).php:1).

Поддерживаются маршруты:

- `POST /register` - регистрация устройства
- `POST /data` - прием телеметрии
- `GET|POST /sync_time` - выдача времени
- `POST /control` - устройство запрашивает желаемое состояние реле
- `GET|POST /relay_set?device_id=...&state=on|off` - установка команды реле
- `GET|POST /relay_state?device_id=...` - чтение команды реле

## Локальное хранение

Телеметрия пишется в файл:

- `/queue.bin`

Используется кольцевой буфер поверх `LittleFS`. При переполнении старые записи вытесняются новыми.

## Сборка

Проект рассчитан на `PlatformIO`.

Основной профиль:

- `env:esp32doit-devkit-v1`

Пример команды:

```powershell
pio run
```
